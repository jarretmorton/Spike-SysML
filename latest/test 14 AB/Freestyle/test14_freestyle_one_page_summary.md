# Test 14 (Freestyle Arm) — One-Page Summary

**Task.** Drive the rover straight at a wall (~1 m away) at maximum speed and stop as close as possible without touching it. Two hard constraints: *run at maximum speed* and *no contact*. Unlike the systems-engineering arm, this arm was given no prescribed method — free to develop and calibrate however it judged best, then lock one program and run it five times.

**Result.** All five operation runs stopped with no contact, **19–35 mm** from the wall (mean **28.8 mm**) at full speed, in **four characterization runs** — one lost to a memory error — and **one operator measurement**. Repeatability was strong: every stop came from the normal trigger with no safety stop firing, heading was within 0.1° of straight on all five, and speed held at 424–458 mm/s. The arm also froze a gap estimate for each run before asking for the measured values; those ran low by 3.4 mm, with ~2.9 mm of scatter.

**What went wrong, and how it was corrected:**

- **A faulty forward sensor — dropped for the right outcome, on a partly wrong diagnosis.** The rover carries two forward ultrasonic sensors. In run 1, sensor B froze at 588 mm for 190 ms then jumped 104 mm. The arm read this as cross-talk — two ultrasonics pinging one flat wall and hearing each other's echoes — and fixed it by never using B at all, landing on the good sensor and killing the interference in one move. But cross-talk is symmetric and would have justified dropping *either* sensor, and the arm never measured B against ground truth, so it never learned B is genuinely faulty. It chose right on B-specific evidence, not on a diagnosis.

- **Heading collapse at full speed — found early, then designed out.** Run 1 held heading within ±1° at a regulated 300 deg/s, then drifted **−18° in one second** the instant full speed was commanded. Cause: at full speed the motor controller saturates, speed regulation silently stops working, and the natural ~9% mismatch between the motors goes uncorrected. The fix: command full power directly rather than request a speed, and close a steering loop on hub heading that *trims only the inner wheel*, so at zero heading error both sides still sit at full power and no speed is given up. Straight and fast stopped being a trade rather than a compromise — heading error at the brake was ≤0.1° on every operation run.

- **Telemetry — one characterization run lost outright.** Run 2 failed partway through with a memory error: the telemetry log grew without bound at 200 Hz until memory ran out. The rover braked safely, but every number from that run was lost. Fix: a fixed-size buffer allocated up front, logging thinned to 50 Hz from a 200 Hz control loop, and fewer values per sample — ~20 KB instead of ~115 KB. It cost one of four characterization runs.

- **The measurement it asked for was too coarse to fully use.** After run 3 the arm parked the rover at a resting sensor reading of 174.05 mm and asked the operator for one number: the true gap to the wall. Answer, 151 mm — a 23.0 mm sensor-to-bumper offset, cross-checked to within 2.5 mm against an independent inference from the start line. That let the arm target a 50 mm sensor reading knowing it meant roughly 27 mm of clearance. But a single measurement at 174 mm cannot separate a fixed offset from a scale error, and the operating point is near 48 mm — the source of the 3.4 mm bias, caught by the arm itself at close-out.

**Stopping-algorithm changes (top level).** The stop command never changed — a motor hold on both motors. What changed was what decides the trigger: (1) Drive at full power under the heading steering loop, replacing regulated-speed drive. (2) Blend sensor and wheel travel: each fresh reading becomes a reference point corrected for the sensor's lag, and between readings the estimate rides on wheel rotation. Necessary, not optional: the sensor updates only 31–41 times a second, lags tens of milliseconds, and once froze for 144 ms while the rover covered 62 mm. (3) Add an **asymmetric outlier check** after a bogus 939 mm reading became the reference point and threw the estimate 110 mm too far: a reading may now sit at most 25 mm *above* the wheel-based prediction but 70 mm below it, since a high reading near the wall is the one error that causes contact. (4) Compute braking distance from the *live measured* speed, so a sagging battery shortens the trigger automatically. Run 4 validated the finished program — its on-board model called the final distance to 0.5 mm, at an estimated true gap of 23 mm — and it then ran unchanged for all five operation runs. One announced change was never made: the arm said it would swap the motor hold — which settles 6–8 mm behind the closest approach — for a passive brake. The locked program kept the hold.

**What held by luck.** The program discards any reading below 45 mm as invalid, but the rover parks at 41–51 mm — so on two of five runs it threw away good readings and blanked its own final estimate, recovered by hand from the raw trace. A few millimetres closer and it would have been blinded entirely. That same threshold gates the hard-floor safety stop, leaving it blind in the band nearest the wall — the report treats it as a reporting problem only. Second, after 250 ms with no accepted reading the outlier check is bypassed entirely — it only ever did so far from the wall, where a bad reading was affordable. Third, the calibration error pointed the safe way — the opposite sign would have put the rover ~4 mm closer than it believed, not farther.

**Score against the criteria.**
1. Characterization/verification runs (fewer better): **4** (one yielded no data, lost to the memory error).
2. Human interventions (fewer better): **1** — a single operator gap measurement during characterization (operation gaps were measured at close-out, for scoring only).
3. Operation runs with no contact (more better): **5 / 5**; wall contacts across the whole test, characterization included: **0**.
4. Closeness of stops: **19–35 mm, mean 28.8, best 19, sample standard deviation ≈6.6 mm**.
5. Predicted vs actual error: **28.8 mm − 23 mm = +5.8 mm** — 5.8 mm farther out than the 23 mm true gap verified on run 4, the last run before the program was locked without further edits (a single sample, which the arm flagged as thin). Separately, the five onboard estimates, frozen before ground truth, ran low by 3.4 mm.
