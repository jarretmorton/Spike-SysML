# Test 12 (SE Arm) — One-Page Summary

**Task.** Drive the rover straight at a wall (~1 m away) at maximum speed and stop as close as possible without touching it. Two hard constraints: *run at maximum speed* and *no contact*. The arm followed a gated systems-engineering process — analyze, model, calibrate, verify, then five scored runs — touching hardware only after the analysis.

**Result.** All five operation runs stopped with no contact. Four landed 13–33 mm from the wall (mean 22, operator-measured); the fifth stopped 236 mm out after a false trigger (below). Excluding that outlier the stops were tight — best 13 mm, spread ~8 mm — five times closer than freestyle's 124. The core strength was predict-then-verify: before any scored run it froze a 50 mm verification gap, then measured 55 mm — held to +5 mm. Getting there took three calibration and two verification runs (one lost to a software fault) against a three-run plan, plus one operator measurement. The result was real, but two headline claims — a "zero-error" model check and "sub-millimetre" accuracy — are artifacts of how the numbers were combined, not evidence the model was that good.

**What went wrong, and how it was corrected:**

- **Backward run on the second calibration.** The first calibration run misread which motor sign drives forward: it read direction from the rover's turning angle (which can change without the rover going anywhere) and ignored the rear sensor's steadily dropping reading — the direct evidence it was moving *backward*. The second calibration run then reversed for 19 s and backed into a surface behind it — the test's one impact — before ending. Fix: directions were re-derived from the rear sensor and confirmed on the re-run.

- **A faulty ultrasonic sensor — found and excluded.** The two forward sensors disagreed by 176 mm on the same wall at the start, and during the approach one froze on a stale value for 0.3 s at a time. The arm chased this rather than assuming geometry: comparing how fast each reading fell as the rover closed in, it found one angled off the wall and cut it from the stop decision. A good catch — but it left a single forward sensor with no cross-check, and that channel is itself noisy, which set up Run 5 below.

- **Yaw — actively corrected, but not fully understood.** Unlike freestyle, this arm steered: a heading controller nudged the wheels' speeds to hold a straight line. The correction was first written with the wrong sign — it would have *worsened* drift — caught in analysis before running. Then a subtler issue: the commanded speed exceeded what the motors deliver, so both saturated and the correction did nothing; lowering it to the true ceiling gave it authority, cutting peak drift ~10° to ~5°. But its steady-state behaviour was never derived — the plan just "expected drift < 5°" — and Run 5 drift reached 8°.

- **Verification failure, a lost data dump, and the repeat.** The first verification run added a motor-speed read inside the fast control loop. That read threw a transient fault mid-run; the loop exited early, and the telemetry backlog crawled out over a congested wireless link (~170 ms per message vs ~18 ms normal), overrunning the host timeout before the run finished. Fix: the read was removed and the run repeated cleanly, landing 55 mm. The same latency later cost the dump on operation Run 2 — so the run where the rover came closest to the wall (13 mm, on the predicted floor) has no onboard record of where it thought it was.

- **Run 5 stopped 236 mm short — a false trigger.** On the final run the trusted forward sensor threw a spurious short reading — 99 mm with the wall ~236 mm away and nothing in front of it — firing the brake and stopping the rover 236 mm out. There was no object; the sensor simply spiked low, as it did intermittently across the runs, while the *excluded* sensor read a far more plausible 268 mm. No contact — but only because a spurious *short* read brakes early (safe); a *long* or stale one would have suppressed the brake and hit the wall. A guard requiring a few consecutive closing readings before braking would have caught it, and was absent.

**Stopping-algorithm changes (top level).** The stop command itself — a hard motor brake on both wheels when the forward sensor crosses the threshold — never changed. What changed was the approach around it, across three versions: (1) trigger at 122 mm, speed at an *estimated* ceiling, correction present but ineffective (motors saturated); (2) speed-read removed and speed lowered to the *measured* ceiling so the correction engages — the clean 55 mm verification; (3) locked operation — same brake, trigger lowered 122→100 mm using the operator-measured offset to stop closer. Every change was to what *decides* the stop and how straight the rover arrives, never the brake.

**What held by luck.** Two things. First, Run 5's no-contact rested on the direction of a sensor error the arm couldn't control — a short false reading braked early (safe); the opposite error hits the wall. The same directional luck protected freestyle. Second, the tight stops sat at the edge of the margin — Run 2's 13 mm is essentially the predicted 12 mm floor — a best/worst-case timing band, not a full statistical margin; done properly it doesn't clear a three-sigma no-contact bar. Staying clear on the tight runs was nearer luck than the report implies. Separately, the report's "zero-error" model check compares the prediction against a gap computed from the very measurement being checked — it can only come out zero, confirming the arithmetic, not the model.

**Score against the criteria.**
1. Calibration and verification runs (fewer better): **3 calibration + 2 verification** (one calibration run drove backward; one verification run lost to a software fault), vs a 3-run plan.
2. Human interventions (fewer better): **1** — one operator gap measurement at the verification run, placed where the analysis said the leverage was.
3. Operation runs with no contact (more better): **5 / 5**. Impacts across the whole test: **1** — the backward calibration run; operation was contact-free.
4. Closeness of stops: **13–236 mm; excluding the Run 5 false-trigger outlier, mean 22, best 13, standard deviation ≈ 8.5 mm** (with Run 5, mean 65).
5. Predicted vs actual error: frozen prediction **26 mm**. Excluding the Run 5 outlier, actual − predicted = **−4 mm** (mean 22); across all five, **+39 mm** (mean 65), dominated by the false trigger.
